I'm a developer at a web agency in Nepal. I've just been put in charge of all our server work, and I'm starting from zero.
This site is my notebook for learning [Railway](https://railway.com). I learn it CLI-first, mostly by asking Claude to run commands for me.

- **Days:** what I practiced each day, newest first.
- **Use cases:** practical Railway tasks, such as deploying an app or adding a database. Each one has the command syntax, a real example and an AI prompt.
- **Cheatsheets:** every [Railway command](/cheatsheet/railway-cli/) I've used and every [error I've hit](/cheatsheet/troubleshooting/).

Every command has a color type and an **AI prompt**, the plain-English request I give Claude to run it:

| Color | Type | Like HTTP | Meaning |
| --- | --- | --- | --- |
| 🟢 | **VIEW** | GET | Only looks. Changes nothing. Safe anytime. |
| 🔵 | **CREATE** | POST | Makes something new. |
| 🟡 | **EDIT** | PATCH | Changes one part of something that exists. |
| 🟠 | **UPDATE** | PUT | Replaces, redeploys or syncs something as a whole. |
| 🔴 | **DELETE** | DELETE | Removes, stops or discards. **Can't be undone.** |

The [Railway week plan](/plan/) is my route for covering all of Railway. Everything else (days, use cases, cheatsheets) appears only after I've actually practiced it.
